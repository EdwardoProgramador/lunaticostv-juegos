# Los objetos del Cholo · lib/

Every page loads `lib/cholo.css` and `lib/vendor.js` first. Nothing else is shared by copy-paste: if it's in two pages, it lives here.

## Level 2 · El Cuarto del Cholo (10–19)

| File | What it does | Used by |
| --- | --- | --- |
| `level2-text.js` | **Every on-screen text of level 2 (Spanish) in one list** (`TEXT`), plus the puzzle data: `ALTAR_ORDER` (correct order, left → right: vela, libreta, cassette, micrófono, medalla) and `MOON_PHASE` (phase drawn per object). Translate by copying `TEXT` and changing the strings. | all level 2 files |
| `room-page.js` | Page shell for 09–19: header (label, controls, Repetir, Escritorio/Móvil), stage with the mock site, and the full-screen room overlay (title, X, hint, big title). X closes the room; the room button in the mock header reopens it. Helpers: `select`, `button`, `sparks`, `flyIcon`. `roomPage({ room: false })` = mock site only (15, 18, 19). | 09–19 |
| `room.css` | Room overlay chrome: title top-left, X, hint, big title, drop zones, drag ghost; safe areas; on real phones the page controls move under the X. | 09–19 |
| `room.js` | The 3D room: plaster walls, worn wood floor, fog, smoke and dust; the shared altar with 5 places (copper plinth each, and the moon phase for that place carved into the altar's wood front below it; the engraving lights up in copper while an object stands there); the main candle (the light that casts the puzzle shadows); the ornate painting as a hinged door (`openPainting`) over a niche; camera framing per focus (`full`, `altar`, `crystal`, `painting`, `niche`) that respects the title/tray, mouse parallax on desktop and idle drift on touch, shake; object placing, place light-up, candle flare and cold flicker. Painting: night clouds over water (`paintingTex`), the same on every room page, on aged canvas. Rendering: aged surfaces (`surfaces.js`) on walls, floor, altar, frame and niche; soft PCF shadows from the main candle (1024², every frame) and the two tall front altar candles (512², refreshed 4×/s); environment captured from the room itself; bloom + ACES filmic output (`room-render.js`). `room.post` = the renderer wrapper. Adaptive quality: `room.quality` (`level` 'high' | 'low' | 'minimal', `mode` 'auto' or a level, `set(mode)`, `onChange(fn)`). High = room reflections, bloom, soft shadows from 3 candles, every candle light real-time, 1024 px surfaces, pixel ratio ≤ 2. Low = the altar candles + front wash baked (light maps on back wall and floor, per-vertex on the altar, frame, candles and niche; flickers with the main candle), only the main candle (the shadow-puzzle light) real-time and casting the one shadow (512²), no bloom, simple environment, pixel ratio ≤ 1.25. Minima = Low without reflections (no environment, a little more fill light), the puzzle shadow at 256², pixel ratio 1. Auto: starts at the detected level and measures the real frame rate in 1.5 s windows: during the first 12 s on screen two fast, steady windows (≥ 55 fps) step UP one level; any time two slow windows (< 40 fps on High, < 27 on Low) step down; a level left for being slow is never retried (no flip-flopping). No recompiles: all three setups are compiled in the background (the starting level + neighbour before `room.ready`, the third right after). Loading: `room.ready`, `room.loading` (progress + step log), loading screen, `prefetchRoom()` (see performance log 3). Closing the room frees its GPU memory; reopening re-runs the GPU warm-up (performance log 5). | 09, 10, 11, 12, 14, 16B, 17 |
| `surfaces.js` | Aged PBR surfaces for the room, altar, painting frame and key (not the 5 objects), pre-baked WebP in `assets/tex/room/` (1024 px) and `assets/tex/room/512/` (Low / phones): `wood` / `woodBox` (worn lighter, smoother uv borders) / `woodBevel` (same maps as wood + wear on bevels, shader), `copper` (tarnish, verdigris, rubbed highlights, scratches, metalness map), `iron` (blackened, rust in pits), `plaster`, `floor`, `canvas` (material params incl. colour + detail maps), `painting` (the picture). `setSurfaceRes(512 | 1024)` swaps the tiered maps in place (one upload per frame, no recompile); `surfaceUrls()` lists the files. | room.js, key.js |
| `room-render.js` | Cinematic output for the room: HDR pass (MSAA) → bloom → ACES filmic + sRGB once at the end; `captureEnv(pos, hide)` renders the room into a cube map (PMREM) used as `scene.environment`, so copper, metal and glass reflect the walls, painting and candles. Bloom threshold is in HDR units (`BLOOM` at the top) and only the capped excess blooms: flames, hot copper and glowing cracks. `setBloom(on)`. Adaptive-quality helpers: `detectQuality(renderer)` (software GPU, max texture < 4096 or phones with < 4 cores / < 3 GB → minimal; other phones/tablets → low; desktops with < 4 cores, < 4 GB or max texture < 8192 → low; else high; `?calidad=alta|baja|minima` forces), `bakeLightMap` / `bakeVertexLight` / `bakedMaterial` (Lambert bake of the candle lights, no shadows) and the shared `BAKE` strength uniform. | room.js |
| `tray.js` | Inventory tray at the bottom of the room (objects HUD look). Slots can be empty (silhouette) or held; extra items (the key). With `onRead`, a hidden "page" slot (the torn clue page, after a separator) that `showPage()` reveals; tapping it reopens the clue. On ≤ 640 px the slots shrink slightly while the page slot is shown so 6 slots fit at 375 px. | 09, 10, 11, 12, 14, 17, 18 |
| `altar-order.js` | Placing the objects: drag (desktop) or tap object → tap place (mobile, drag also works), move again before all 5 are down, swap, tap a silhouette to take an object back. Check: wrong = tremble + cold flicker + back to the tray; right = places light up one by one + flare → `onSolved`. | 09, 10, 11, 12, 14, 16B, 17 |
| `notebook-clue.js` | The clue page: a 2D aged notebook page drawn at runtime (sketches traced from the HUD renders, ink moon phases, the handwritten line in La Belle Aurore), page-turn open/close. ## Performance log

1. Pre-baked textures: all procedural surface maps (room wood/copper/iron/plaster/floor/canvas/painting + the objects' worn maps) are now WebP files loaded asynchronously; the runtime canvas generation (≈1.9 s on a fast desktop) is gone. Edited `cholo-objects.js`, `surfaces.js`, `room.js`, `chest.js`; created `assets/tex/room/*` (23 + 13 × 512) and `assets/tex/obj/*` (17).
2. No runtime recompiles: lights never change during play (the candle object's flame light lives at the scene root at 0 while off the altar; the crystal light + particles are created with the room via `prepareCrystalFX`); glows are emissive/opacity only. `room.ready` = warm-up: textures uploaded, both light setups (High; Low/Minima) compiled with `compileAsync` against their render targets, crystal pre-compiled (`prewarm` registry), env capture + bloom passes, one frame with every object placed. The room doesn't render while closed or warming up. Measured: placing objects and High↔Low switches add 0 programs. Edited `room.js`, `room-render.js`, `cholo-objects.js`, `crystal.js`, `crystal-fx.js`, `chest.js`.
3. Background loading: `createRoom` only sets up the structure (32 ms sync on an A18 Pro, was 95 ms); models, simple environment, Low bake, texture uploads and compiles run in ≤ 8 ms slices between frames (`room.ready`, `room.loading` = progress + step log; no long task during the warm-up); 09 plays the 5/5 HUD right away while the room prepares; 07 prefetches the room's code and textures at idle (`prefetchRoom`); room pages wait for `room.ready`, and a room opened before it's ready shows a loading screen (candle flame + copper progress line, "Encendiendo el cuarto", after 150 ms). Edited `room.js`, `cholo-objects.js` (`textureProgress`), `room.css`, `level2-text.js` (`roomLoading`), pages 07, 09, 10, 11, 12, 14, 16B, 17.
4. Adaptive quality: phones start at Low (weak phones / software GPUs at the new Minima: no bloom, no reflections, only the puzzle shadow at 256², pixel ratio 1), the frame-rate watch steps up as well as down (≥ 55 fps steady to go up, < 40 / < 27 to go down, failed levels locked out), High on a phone streams in the 1024 px surfaces; Minima compiled in the background, so switches still add 0 programs (87 before and after every switch, measured); Minima added to page 10's Calidad select. Notes:
- Candle glass is thin-walled (`thickness: 0`, no attenuation). Volume attenuation is measured in world units, so it changed colour with display scale. Keep any glass tint in `color`/`map`.
- `crescentGeo` is mirrored in z (reversed winding); the candle runs it through `flipWinding` so the moon's front face renders. The altar crescents use it unchanged.
- Shadow puzzle tuning lives at the top of `shadow-puzzle.js`: `TARGETS` (silhouette + the 5 cells), `JAG`/`VSTEP`/`CSTEP` (crack jaggedness), `TINT` and the alphas in `drawShadows`, `DEPTH` (how far each fragment floats from the candle), `ROT`, `START`, and the snap tolerance in the tick (`err < 0.14` rad).
